## New Features

- A new `dontForget.reminderDeleted` hook fires on every client when a reminder disappears from a user's list.
- A new toolbar adds a text filter, a hide-completed toggle, and a clear-completed button. GMs also get a user picker with an explicit all-users option.
- A new world setting turns in-world due dates on or off. With it off the date pickers disappear from the create and edit dialogs and no new Calendaria notes are made, while existing due dates keep their notes.
- Each due date is backed by a hidden Calendaria note that toasts the reminder's owner when the date arrives and flags the reminder as due in the list.
- New `dontForget.reminderCreated` and `dontForget.reminderCompleted` hooks fire on every client, flagged with whether the change came from another client.
- Note creation, moves, and deletion are relayed through the ATLAS primary GM, so players without note permission can still set due dates. Setting a due date warns when no primary GM is connected.
- Other modules can create, update, complete, and delete reminders through a public API at `game.modules.get('dont-forget').api` and `globalThis.DONTFORGET.api`.
- Reminder labels can be renamed in place by clicking them. A quick-add field creates a reminder on Enter, or carries its text into the full create dialog.
- Reminders can carry a `ref` key so a module can tag which of its own entities a reminder is about. A new `findReminders` API query filters by source, ref, owner, or completion state.
- Reminders can carry an in-world due date picked from Calendaria in the create and edit dialogs, shown on the reminder row when Calendaria is active.
- Reminders record which module made them. A module that declares a different source is refused when it tries to edit, complete, or delete another module's reminder.
- Removing a due date, deleting or clearing the reminder, or deleting the backing note clears the link on both sides.
- The open reminder window refreshes live when reminders change on any client.
- The reminder list sorts due-and-arrived reminders to the top, then reminders by due date oldest first, then undated ones, with completed reminders last.
- The reminder window is rebuilt as a compact row list on the ATLAS theme instead of a table.

## Bug Fixes

- A GM viewing another player's list is no longer snapped back to their own list on every render.
- A user first seen after startup no longer reports their entire existing list as newly created.
- Creating a reminder for another user is refused unless you are a GM.
- Creating a reminder now only reports success when one was created. A permission failure no longer shows a false "reminder created" notification.
- Reminder updates write only the changed fields, so two clients editing the same list no longer clobber each other's changes.
- The list no longer re-renders under you while a text field in the window has focus.
- The module stylesheet is now loaded by module.json, so the reminder window picks up its styles.
- The reminder checkbox tooltip reads "mark not done" when the reminder is already complete instead of always reading "mark done".

## Changes

- A permission failure while clearing completed reminders is reported once per affected user rather than once per reminder.
- Clearing completed reminders saves once per owning user instead of once per reminder.
- Text fields, dropdowns, checkboxes, and buttons in the reminder window follow the ATLAS palette instead of Foundry's default styling.
- The create and edit dialog buttons and the rename tooltip pull their text from the shared ATLAS strings instead of module copies.
- The create and edit reminder dialogs build their contents from one shared context, so both show the same fields, placeholder text, and owner picker.
- The delete reminder and delete all completed confirmation prompts carry the module class, so they render in the ATLAS theme instead of Foundry's default dialog styling.
- Verified compatibility raised to Foundry v14.366.
